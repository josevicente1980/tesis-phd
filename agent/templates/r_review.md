# Criterios de evaluacion

- Reproducibilidad del flujo de trabajo.
- Claridad y legibilidad del codigo.
- Uso adecuado de paquetes y funciones.
- Robustez ante errores, datos faltantes y cambios de ruta.
- Separacion entre preparacion de datos, analisis y presentacion.
- Eficiencia computacional.
- Consistencia de nombres de objetos, variables y funciones.
- Trazabilidad entre datos de entrada y resultados.
- Integracion con Quarto y el documento final.
- Riesgos de efectos secundarios, dependencias ocultas o estado global.

# Checklist

- [ ] El codigo tiene un proposito claro.
- [ ] Las rutas son reproducibles y no dependen de ubicaciones locales fragiles.
- [ ] Los paquetes requeridos estan declarados.
- [ ] Los datos de entrada existen y estan documentados.
- [ ] Los objetos intermedios tienen nombres claros.
- [ ] Las transformaciones son comprensibles y trazables.
- [ ] Los supuestos analiticos estan explicitados.
- [ ] El codigo maneja valores perdidos o casos excepcionales.
- [ ] No hay duplicacion innecesaria de bloques logicos.
- [ ] Las funciones reutilizables estan separadas del analisis puntual.
- [ ] Las tablas y figuras generadas son reproducibles.
- [ ] No hay escritura accidental de archivos fuera de rutas previstas.
- [ ] El codigo evita resultados dependientes de estado previo no declarado.
- [ ] El rendimiento es razonable para una compilacion completa.
